Sorting Station State Machines

Simplified version. The controller consists of three kinds of state machine: a sorter, a conveyor and two instances of an ejector. The sorter starts as soon as the machine is switched on. It handles one part on the belt at a time, and there is no fault handling.

Overview: who talks to whom

Each machine owns its outputs. Only the conveyor switches the belt, only an ejector switches its valve. The sorter sends them commands and waits for the ejectors to report back.

Sorter

Follows one part from the entry to its bin. The colour read by the photoSensor decides the target. In ToEjector the machine waits for the sensor of its ejector, so a blue part simply passes B3. Bin 3 has no sensor, so ToEnd uses a timeout.

{{3_sorter}}

Ejector (two instances)

One generic definition, used twice: Ejector 1 with valve = valve1, S_in = S1, S_out = S2; Ejector 2 with valve2, S3, S4. It retracts by itself once the cylinder is fully out, then reports done.

Conveyor

The smallest machine. A good first exercise, and it shows why the sorter sends commands instead of switching the belt directly.

Ideas for follow-up exercises

  • Add timeouts to the ejector: what happens if a cylinder gets stuck?
  • Add a start and stop button: which machine should own them?
  • Allow several parts on the belt: keep a queue of targets instead of one variable.
  • Implement the machines in IEC 61131-3 (CASE statement or SFC) and test them against a simulation.
